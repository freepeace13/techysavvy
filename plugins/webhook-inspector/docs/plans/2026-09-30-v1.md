## Approach
Everything lives in `plugins/webhook-inspector/`, shaped like `drop-share` on the server side (config, migration, models, a service, throttled routes, a scheduled prune command) and like `qr-forge` on the client side (Vite IIFE bundle exposing an Alpine component, `node --test` tests). `BinService` owns all bin/request logic; controllers are thin. The capture route is registered **outside** the `web` group so it has no session/CSRF; every other route is inside it. Host is only touched by the scaffold's `host/composer.json` line; root `Makefile` and CI get the plugin's build/test lines.

Naming note (from the spec's schema): `webhook_inspector_bins.bin_id` is the public 16-char capture id; `webhook_inspector_requests.bin_id` is the FK to `webhook_inspector_bins.id`.

Commands below run from the repo root unless they start with `cd`. `PHPUNIT` = `(cd plugins/webhook-inspector && vendor/bin/phpunit)`; `NODETEST` = `npm test --prefix plugins/webhook-inspector`.
